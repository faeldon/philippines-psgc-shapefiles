the files in [`dist/`](dist/) reflect it. Newest first. Each title links to PSA's announcement.

| Status | Meaning |
| --- | --- |
| ✅ | The update is applied to the files in `dist/`. |
| ✅ (NC) | PSA reported no change for the period, so there was nothing to apply. |
| ❌ Pending | The update is not applied yet. |

## Data corrections

Changes to files already in `dist/` that aren't PSGC updates, newest first.

**October 2026: the shapefiles moved to Releases.** The zips are no longer in `dist/`: each PSGC
quarter is a [GitHub release](https://github.com/faeldon/philippines-psgc-shapefiles/releases) with
its zips, its CSVs and a `SHA256SUMS`, and `releases/latest/download/<file>` always serves the newest
quarter. Complete's Level 4 zip is `PH_Adm4_BgySubMuns_complete.shp.zip` there. `dist/` keeps the
CSVs, and `dist/README.md` lists the new addresses. Nothing in the repository needs `git-lfs` any
more. The files' contents are unchanged.

**October 2026: `geom_src` and `dist/complete/` in Level 4.** `PH_Adm4_BgySubMuns` gains a
`geom_src` column, after `geo_level`, saying where each shape comes from (`source`, `dissolved`,
`plotted`, `approximated` or `none`). A second copy of Level 4, `dist/complete/`, approximates the
shapes `dist/` leaves out. Levels 0–3 are unchanged in columns.

**October 2026: one layer per shapefile zip.** Each `.shp.zip` now holds a single layer in
EPSG:32651 (WGS 84 / UTM zone 51N), and its attribute table matches the level's CSV row for row,
including the parent-code corrections below. If you read these files:
- **One layer, renamed members.** The zip holds `PH_AdmN_*.shp`, `.dbf`, `.shx`, `.prj` and
  `.cpg` (it was `PH_AdmN_*.shp.shp` and so on). An older WGS84 lat/long layer (`Regions.shp`,
  `Provdists.shp`, `Municities.shp`, `BgySubMuns.shp`) stored first in the Level 1–4 zips is gone,
  and with it the PSA columns it carried (`pop_2015`, `pop_2020`, `city_class`, `inc_class`,
  `urb_rur`, `status`). Join the [PSGC datafile](https://psa.gov.ph/classification/psgc) by PSGC
  code for those.
- **Names trimmed.** 80 Level 3 and 2,774 Level 4 names lost a trailing space, in the zips and the
  CSVs. Codes, row counts and boundaries are unchanged.
- **UTF-8.** Each `.cpg` now declares UTF-8 (it said ISO-8859-1), so names such as "Las Piñas" read
  correctly in tools that honour it.

**October 2026: parent codes in the Level 2–4 CSVs.** Every parent code (`adm1_psgc`, `adm2_psgc`,
`adm3_psgc`) in `PH_Adm2_ProvDists.csv`, `PH_Adm3_MuniCities.csv` and `PH_Adm4_BgySubMuns.csv` now
exists in the level above. Row counts are unchanged. If you join on these files:
- **Level 2:** the BARMM interim province is now `1999900000`, "Interim Province Code for 63
  barangays of BARMM…" (it was `1909900000`, with no name).
- **Level 3:** cities that PSA places under no province now carry their geographic province or NCR
  district as `adm2_psgc` (e.g. City of Angeles → Pampanga `305400000`, Caloocan → NCR Third
  District `1307500000`, Davao City → Davao del Sur `1102400000`), not their own code.
- **Level 4:** those cities' barangays carry the same `adm2_psgc`; Manila's 14 sub-municipalities
  and their barangays are under the City of Manila (`1380600000`), not `0` or a sub-municipality
  code; two non-barangay areas are named (Manila North Cemetery, Tutuban Mall).
